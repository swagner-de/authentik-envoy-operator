# Authentik Envoy Operator

A Kubernetes operator that automates OIDC authentication with Authentik. It provisions Authentik OAuth2 applications and, optionally, fronts your HTTPRoutes with Envoy Gateway `SecurityPolicy` resources.

## Overview

This operator watches `OIDCApplication` custom resources and:

1. Creates/adopts an OAuth2 provider and application in Authentik (idempotently, keyed on a stable slug)
2. Manages Authentik groups (reference existing or create) and binds them to the application for access control
3. Optionally renders an application Secret from `spec.secretTemplate` (for apps that speak OIDC natively)
4. Optionally creates an Envoy Gateway `SecurityPolicy` per target HTTPRoute (OIDC login, JWT validation, group-based authorization)

An `OIDCApplication` with no `targetRefs` is **standalone**. With `targetRefs`, it is additionally **fronted by Envoy**. Application Secret output is independently enabled by a nonempty `secretTemplate`.

## Prerequisites

- Kubernetes 1.28+
- Authentik instance with an API token
- Envoy Gateway 1.0+ `SecurityPolicy` CRDs and Gateway API `HTTPRoute` CRDs. The manager currently registers watches for both APIs at startup, even when no application uses `targetRefs`; Envoy functionality is used only when `targetRefs` is set.

## Installation

### Helm

The chart is generated by Kubebuilder (`helm.kubebuilder.io/v2-alpha`) and lives at `dist/chart`. Releases publish it as an OCI artifact.

```bash
# From the OCI release (recommended)
helm install authentik-envoy-operator \
  oci://ghcr.io/authentik-envoy-operator/charts/authentik-envoy-operator \
  --version <version> \
  --namespace authentik-system --create-namespace

# Or from a local checkout
helm install authentik-envoy-operator ./dist/chart \
  --namespace authentik-system --create-namespace
```

## Custom Resources

### AuthentikProvider (cluster-scoped)

Defines the connection to an Authentik instance:

```yaml
apiVersion: authentik-envoy-operator.io/v1alpha1
kind: AuthentikProvider
metadata:
  name: main
spec:
  host: "https://authentik.example.com"
  apiTokenSecretRef:
    name: authentik-api-token
    namespace: authentik-system
    key: token
  authorizationFlowSlug: "default-provider-authorization-implicit-consent"
  invalidationFlowSlug: "default-provider-invalidation-flow"
```

### OIDCApplication (namespaced)

**Standalone** - provision Authentik and optionally emit an application Secret for a natively-OIDC app:

```yaml
apiVersion: authentik-envoy-operator.io/v1alpha1
kind: OIDCApplication
metadata:
  name: grafana
  namespace: monitoring
spec:
  providerRef:
    name: main
  displayName: "Grafana"          # Authentik app name; defaults to metadata.name
  signingKey: "authentik Self-signed Certificate"   # asymmetric RSA or EC keypair for JWKS verification
  propertyMappings:               # you must include one that emits the `groups` claim
    - "authentik default OAuth Mapping: OpenID 'openid'"
    - "authentik default OAuth Mapping: OpenID 'profile'"
    - "authentik default OAuth Mapping: OpenID 'email'"
  scopes: [openid, profile, email]
  groups:                         # flat list; always bound to the app
    - { name: grafana-admins, create: true, cleanup: true }
    - { name: grafana-users,  create: false }
  redirectURIs:                   # native apps need callback URIs for functional login
    - "https://grafana.example.com/login/generic_oauth"
  secretTemplate:                 # opt in to an application Secret
    GF_AUTH_GENERIC_OAUTH_CLIENT_ID: "{{ .ClientID }}"
    GF_AUTH_GENERIC_OAUTH_CLIENT_SECRET: "{{ .ClientSecret }}"
    GF_AUTH_GENERIC_OAUTH_AUTH_URL: "{{ .AuthorizationEndpoint }}"
    GF_AUTH_GENERIC_OAUTH_TOKEN_URL: "{{ .TokenEndpoint }}"
    GF_AUTH_GENERIC_OAUTH_API_URL: "{{ .UserinfoEndpoint }}"
```

The application Secret is created only when `spec.secretTemplate` is nonempty. Its name defaults to `<name>-oidc` and can be changed with `spec.secretName`; its data contains exactly the rendered template entries, with no implicit keys or merging.

Upgrading from the old implicit nine-key Secret requires an explicit compatibility template. See [Migrate the former fixed-schema Secret](docs/docs/getting-started.md#migrate-the-former-fixed-schema-secret).

**Envoy mode** - add typed `targetRefs`; the operator derives the `/oauth2/callback` redirect URIs from the routes' hostnames and builds a `SecurityPolicy`:

```yaml
spec:
  # ...same as above, plus:
  forwardAccessToken: true
  targetRefs:
    - group: gateway.networking.k8s.io   # default
      kind: HTTPRoute                     # default
      name: grafana-route
```

## How It Works

1. Resolves the `AuthentikProvider` to get API credentials and flow UUIDs
2. Resolves/creates groups and resolves the signing key + property mappings by name in Authentik
3. Builds redirect URIs from `spec.redirectURIs` plus `https://<hostname>/oauth2/callback` for each targetRef HTTPRoute
4. Idempotently adopts-or-creates the OAuth2 provider and application keyed on the stable slug `<namespace>-<name>` (override with `spec.slug`, immutable). The operator owns any Authentik object under that name.
5. Binds the listed groups to the application
6. If `secretTemplate` is nonempty, renders the application Secret; if `targetRefs` are set, separately writes the fixed `<name>-envoy-oidc` Secret containing exactly `client-secret`
7. If `targetRefs` are set, creates a `SecurityPolicy` per route referencing that fixed Envoy Secret, with OIDC config, JWT validation (remote JWKS), and group-based authorization on the `groups` claim

| `secretTemplate` | `targetRefs` | Secret output | SecurityPolicy output |
|------------------|--------------|---------------|-----------------------|
| Empty | Empty | None | None |
| Nonempty | Empty | Application Secret only | None |
| Empty | Nonempty | Fixed `<name>-envoy-oidc` Secret only | One per targetRef |
| Nonempty | Nonempty | Application Secret and fixed Envoy Secret | One per targetRef |

`spec.secretName` affects only the application Secret. The Envoy Secret name and its single `client-secret` key cannot be overridden.

> **Note:** authorization matches the token's `groups` claim, so your `propertyMappings` must include a mapping that emits `groups`. The `signingKey` must be an asymmetric (RSA/EC) keypair so Envoy can verify tokens via JWKS.

## Authentik API Token Permissions

- `authentik_core`: view/add/change/delete `application`; view/add `group`
- `authentik_providers_oauth2`: view/add/change/delete `oauth2provider`; view `scopemapping`
- `authentik_policies`: view/add/delete `policybinding`
- `authentik_flows`: view `flow`
- `authentik_crypto`: view `certificatekeypair`

(Group `add`/`delete` are only needed if you use `create: true` / `cleanup: true`.)

## Metrics

The operator exposes Prometheus metrics:

| Metric | Type | Description |
|--------|------|-------------|
| `oidcapplication_reconcile_duration_seconds` | Histogram | Reconcile loop duration |
| `oidcapplication_reconcile_errors_total` | Counter | Reconcile errors by type |
| `oidcapplication_status` | Gauge | Application status (1=ready, 0=not ready) |
| `authentikprovider_connected` | Gauge | Provider connectivity (1=connected) |
| `authentik_api_requests_total` | Counter | Authentik API requests by endpoint/status |
